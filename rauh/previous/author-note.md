# Say It Plainly — note for the author

1. Look first at the editor (screenshot-edit-open.png): does a stranger see, before choosing, which paragraph "hurts most"? The game turns on that judgement. The best two-edit plan is the Commissioner's quote rewritten with verbs plus the last paragraph in everyday words (46.7). The natural first-timer move, splitting the long opening sentence, falls just short (39.5).
2. Every number is in the `CONFIG` block at the top of `mechanism.js`, the only copy of the mechanism. Each line is tagged with its source: Fig. 2 values read off at 400 dpi, or "our choice". The invented press release and its rewrites sit just below it in `RELEASE`. Edit, run `node fidelity.js` (it checks the syllable count of every word against a hand count, and the game balance), then `python3 build.py`. The build refuses to finish if the embedded mechanism differs from the file.
3. What we were least sure about: (a) the benchmark values are read off a figure, not taken from tables (±1 point); the replication data on Dataverse would fix this. (b) The release is ours, not a real Commission text, so the editor shows how the measure works, not a finding of the paper. (c) The end screen's lesson, "long words weigh heavily", holds on Flesch reading ease, the paper's measure. On Flesch–Kincaid grade, splitting sentences counts for more, though the single best edit stays the same (fidelity-result.txt).

This game has had the builder's review only: screenshots and a scripted browser session at 380 px. It has not been played by real strangers, and the four-minute length is an estimate.
